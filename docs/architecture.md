# RED Loop architecture

## Three deliberately separate execution contexts

1. **Web dashboard:** buildless HTML/CSS/ES modules, delivered by a Cloudflare Worker with an Assets binding. `web/loop.js` is a finite, bounded demo state machine. Messages/events exist only in tab memory. No chat backend, API credentials, telemetry SDK, or cross-tab command channel exists.
2. **ChatGPT page:** `userscripts/red-loop.user.js` provides the real, explicitly started continuation panel. The Safari Web Extension packages that same source byte for byte. It only matches `chatgpt.com` and the legacy `chat.openai.com`, never frames. It uses the visible composer and normal send button. The worker cannot start it.
3. **Native iOS host:** SwiftUI app, local demo model, activation help and privacy. App controls affect its own demo. It does not claim to know Safari's website permission state or control a Safari tab. Safari website access is granted by the user through the official extension interface.

## Safety boundaries

- Maximum 50 continuations per explicitly started session, minimum 1.
- Start is ignored during an active run. Cancellation invalidates pending demo callbacks.
- The userscript waits for a stable assistant response, checks generation and draft states, then inserts a fixed continuation prompt into an empty editor.
- After sending, the previous response cannot trigger a second send. A new response must appear; a 90-second timeout stops an unacknowledged send.
- Hidden tabs, focus loss, navigation, existing drafts and detected response errors stop real execution. Reload never auto-resumes a stored run.
- Session storage contains only counters/limits per chat. Message text used for local change detection is kept in memory, never logged or transmitted to the worker.
- No `postMessage` command listener, broad host permissions, native credential bridge or background scheduler exists.
- The extension handler returns version metadata only; no native messaging permission is requested.
- Static asset responses carry a restrictive Content Security Policy, no-referrer policy, MIME protection and denied device capabilities. Mutating HTTP methods return 405; `/health` exposes no secrets.

## Build structure

`npm run build` copies `web/` to ignored `dist/`, makes the downloadable userscript, and synchronizes the extension resource. Wrangler serves the assets and health route. Dependencies and lockfile are committed; there are no runtime npm dependencies.

`ios/REDLoop.xcodeproj` contains the REDLoop app, embedded REDLoopExtension appex, and REDLoopTests target. Its shared REDLoop scheme includes XCTest. The committed project is reproducibly generated by `python scripts/generate-ios-project.py`; generation is not required to open or build it.

`scripts/ios-ci.sh` selects an available iPhone simulator, builds/tests, then creates an **unsigned** generic iOS archive. `scripts/ios-sign.sh` uses Codemagic's securely imported profiles for a separate signed archive and IPA export. A successful simulator test would not verify website permissions or physical device behavior.

## Existing vendor snapshot

The repository already contains a `vendor/userscripts/` upstream snapshot, including a nested duplicate. It is retained untouched. RED Loop's new app does not link, embed or compile this vendor tree. The README previously said nothing was vendored; that statement was inaccurate. The independent Userscripts app remains an optional host for importing the RED Loop script, under its own license.
